Local verification¶

Run numerical checks locally from the repository root. GitHub Actions builds this website, checks documentation links and runs Python tooling tests; it does not execute MATLAB or establish numerical correctness. A green documentation check is separate from the MATLAB verification record below.

Choose the checks for your installation¶

H2-store unit and numerical tests require the pinned MRST dependency and do not need PHREEQC, internet downloads, plots or Parallel Computing Toolbox during the test run. Initialize the submodule beforehand:

addpath(fullfile(pwd, 'tests', 'h2store'));
results = runH2StoreTests();

The runner restores the original MATLAB path and working folder and requires every test to pass without skips. It can also accept an existing pinned MRST checkout as its argument.

For biochemistry tests, first follow Installation and initialize H2sim:

startupH2sim('phreeqc', true)
mrstModule add test-suite
checks = runtests(fullfile(pwd, 'tests', 'biochemistry'));
assertSuccess(checks);

Some tests require a PHREEQC engine or optional parallel support. Inspect incomplete results separately; a skipped test does not validate its backend. The fully configured verification record below contains no incomplete tests.

Complete-cycle and serialized-restart regressions require working PHREEQC:

addpath(fullfile(pwd, 'tests', 'cycles'));
cases = runStorageCycleRegressions();

This runner checks two four-cell cases: black-oil dissolution/vaporization and reactive biochemistry with PHREEQC. Each has six steps spanning injection, shut-in and production. A MAT-file checkpoint within shut-in is loaded into a fresh model and solver before resuming production. The PHREEQC check also uses a fresh engine session. Physical-state bounds, well control changes, hydrogen inventory accounting for the black-oil case, reaction consumption, restart agreement and the reviewed saved reference must pass. Missing dependencies or failed comparisons raise an error; the runner never regenerates references.

See the cycle regression guide for comparison bounds, reference provenance and diagnostic inspection commands. Run test folders explicitly after activation; they are intentionally outside the runtime module path.

Platform and scientific limits¶

The stated minimum for core workflows is MATLAB R2021a. This record does not establish results on every MATLAB release. Native Linux PHREEQC coupling is implemented, but a complete native-Linux MATLAB regression run is not recorded here. Native-interface chemistry tested with Windows DLLs is not a substitute for an end-to-end Linux run. macOS sequential PHREEQC coupling is unsupported.

The hybrid PE diagnostic remains history-sensitive and is reported separately from physical restart comparisons. The existing checks require finite PE and retain it in the uninterrupted reference; they do not require PE restart equality. See Code reference for the chemistry ownership and restart details.

These are unit checks and small numerical cases, not full paper-duration simulations, exhaustive phase-transition coverage, or an independent reactive elemental-conservation audit. Reference agreement detects numerical change; it does not prove that every physical model is correct. Papers and archived figures may use different grids, schedules and parameter sets.

Record a new environment¶

When reporting another validation run, record the MATLAB version and platform, H2sim commit, pinned dependency revisions, backend and library version, and all passed/failed/incomplete counts. From the checkout, capture:

git rev-parse HEAD
git submodule status

version
computer
which BiochemistryModel

Keep earlier results as dated records. A reference update must explain the numerical change and retain a before/after review; do not regenerate a reference or relax its bounds simply to make a failing test pass.
